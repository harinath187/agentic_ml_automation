====================================================================
AGENTIC AI BASED AUTOMATED ML PIPELINE
COMPLETE IMPLEMENTATION PLAN
====================================================================

PROJECT STATEMENT:
Build an agentic AI based automated ML pipeline that can take an
input, automatically prepare and analyse the data, identify suitable
ML approaches, run relevant models, evaluate their performance, and
recommend the most appropriate model for the given business use case
with a report.

====================================================================
1. CORE DESIGN PRINCIPLE (DATA PRIVACY BOUNDARY)
====================================================================

The LLM (Claude/GPT/Groq) acts ONLY as a planner, code-writer, and
result-interpreter. It never touches raw data rows.

    LLM sees:  column names, data types, business description,
               aggregated stats, metrics, logs, error messages

    LLM never sees: raw rows, individual sensitive values, PII

    Actual data processing (cleaning, training, evaluation) happens
    in a sandboxed Python execution environment that you control.

Rule: LLM writes/decides -> Code executes on data -> Only metrics/
summaries flow back to LLM.

====================================================================
2. SYSTEM REQUIREMENTS MAPPING
====================================================================

Problem statement requirement        -> System component
--------------------------------------------------------------
Take an input                        -> Data Ingestion Module
Automatically prepare/analyse data   -> EDA + Cleaning + Feature Eng.
Identify suitable ML approaches      -> Planner Agent (problem-type
                                         classifier)
Run relevant models                  -> AutoML Training Tool
Evaluate performance                 -> Evaluator Agent + Metrics
Recommend most appropriate model     -> Decision logic in Evaluator
Report                                -> Reporter Agent + Report
                                         Generator

====================================================================
3. HIGH-LEVEL ARCHITECTURE
====================================================================

    User Input Layer
    (CSV/DB + problem description text)
            |
            v  (schema + business context only)
    PLANNER AGENT (LLM)
    - Understands business goal
    - Decides problem type
    - Creates pipeline plan
            |
            v  (plan/steps)
    EXECUTOR / TOOL LAYER  (sandboxed, touches real data)
    EDA tool -> Cleaning tool -> Feature Engineering tool ->
    Split tool -> AutoML Training tool (AutoGluon/H2O/sklearn)
            |
            v  (metrics, logs, summary stats ONLY)
    EVALUATOR AGENT (LLM)
    - Compares model metrics
    - Decides if retry needed
    - Picks best model
            |
            v
    REPORTER AGENT (LLM)
    - Writes business-friendly recommendation report

6. DETAILED PHASE-BY-PHASE IMPLEMENTATION PLAN
====================================================================

--------------------------------------------------------------------
PHASE 1: FOUNDATION - DATA INGESTION
--------------------------------------------------------------------
Goal: Load data and extract only safe metadata for the LLM.

Tasks:
1.1 Set up project folder structure (as above)
1.2 Build loader.py:
    - Accept CSV/Excel/DB connection as input
    - Load into pandas DataFrame (stays local/sandboxed)
1.3 Build schema extraction function that outputs:
    - Column names
    - Data types
    - Missing value % per column
    - Unique value counts (for categorical columns)
    - Basic stats (min/max/mean/std) for numeric columns
    - Row and column count
1.4 Ensure this schema object (NOT the DataFrame) is the only thing
    passed to any LLM call later

Deliverable: A function that takes a file path and returns a JSON-
like schema summary safe to send to an LLM.

--------------------------------------------------------------------
PHASE 2: PLANNER AGENT
--------------------------------------------------------------------
Goal: LLM understands the business problem and decides the ML
approach and pipeline plan.

Tasks:
2.1 Design prompt template that takes:
    - Business problem statement (free text from user)
    - Schema summary (from Phase 1)
2.2 LLM should output (ideally as structured JSON):
    - Problem type: classification / regression / forecasting /
      clustering
    - Target column
    - Recommended pipeline steps
    - Suggested candidate models to try
2.3 Parse and validate the structured JSON output
2.4 Handle ambiguous cases (ask clarifying question if problem type
    unclear)

Deliverable: planner.py that returns a structured "pipeline plan"
object.

--------------------------------------------------------------------
PHASE 3: EXECUTION TOOLS (DATA-TOUCHING LAYER)
--------------------------------------------------------------------
Goal: Build the actual data processing tools that run locally/
sandboxed, based on instructions from the Planner Agent.

3.1 EDA Tool (tools/eda.py)
    - Missing value analysis
    - Outlier detection (IQR/Z-score)
    - Correlation matrix
    - Distribution checks, seasonality checks (for time series)
    - Output: summary report (text/dict), NOT raw data

3.2 Cleaning Tool (tools/cleaning.py)
    - Missing value imputation (mean/median/mode/forward-fill for
      time series)
    - Outlier handling
    - Encoding categorical variables
    - Duplicate removal

3.3 Feature Engineering Tool (tools/feature_engineering.py)
    - For forecasting: lag features, rolling averages, date/time
      features (day of week, month, holiday flags)
    - For classification/regression: interaction terms, polynomial
      features, scaling

3.4 Splitting Tool (tools/splitting.py)
    - Random split for classification/regression
    - Time-based split for forecasting (NO shuffling)
    - Optionally k-fold or time-series cross-validation setup

3.5 AutoML Training Tool (tools/automl_training.py)
    - Wrap AutoGluon (or H2O-3) to:
      - Accept train/test data
      - Try multiple candidate models
      - Perform hyperparameter tuning
      - Return metrics per model (RMSE, MAE, F1, AUC, accuracy,
        etc. depending on problem type)
    - Output: metrics dictionary only, e.g.
      {"XGBoost": {"RMSE": 120}, "Prophet": {"RMSE": 95}}

Deliverable: A set of callable tool functions, each independently
testable on a sample dataset before wiring into agents.

--------------------------------------------------------------------
PHASE 4: EVALUATOR AGENT + RETRY LOOP
--------------------------------------------------------------------
Goal: LLM compares model results and decides next action.

Tasks:
4.1 Build evaluator.py:
    - Input: metrics dictionary from AutoML tool
    - LLM reasons about which model performs best for the business
      goal (not just lowest error, but interpretability, training
      time, etc. if relevant)
4.2 Decide retry logic:
    - If all models perform poorly (below a defined threshold),
      LLM suggests what to change (different features, different
      imputation, try different model family)
4.3 Implement the loop using LangGraph:
    - Node: train -> Node: evaluate -> Conditional edge: retry or
      proceed to reporting
4.4 Set a max retry limit to avoid infinite loops

Deliverable: evaluator.py + LangGraph loop logic in orchestration/
graph.py

--------------------------------------------------------------------
PHASE 5: REPORTER AGENT
--------------------------------------------------------------------
Goal: Generate a business-friendly report recommending the final
model.

Tasks:
5.1 Build reporter.py:
    - Input: final chosen model, its metrics, business context
    - LLM writes: problem summary, approach taken, models compared,
      final recommendation, business impact explanation, caveats/
      limitations
5.2 Build report template (reports/template.html or docx template)
5.3 Auto-generate report file (PDF/HTML/Word) using Jinja2 +
    WeasyPrint or python-docx
5.4 Include charts/visuals if possible (model comparison bar chart,
    feature importance chart)

Deliverable: A generated report file summarizing the entire run.

--------------------------------------------------------------------
PHASE 6: ORCHESTRATION (TYING IT ALL TOGETHER)
--------------------------------------------------------------------
Goal: Connect all agents and tools into one automated flow using
LangGraph.

Tasks:
6.1 Define the LangGraph state object (tracks: schema, plan, cleaned
    data reference, features, metrics, retry count, final model)
6.2 Define nodes: Planner -> EDA -> Cleaning -> Feature Engineering
    -> Split -> Train -> Evaluate -> (retry or) Report
6.3 Define conditional edges (retry logic from Phase 4)
6.4 Test end-to-end run on a sample dataset

Deliverable: orchestration/graph.py with full working pipeline flow.

--------------------------------------------------------------------
PHASE 7: USER INTERFACE (OPTIONAL BUT RECOMMENDED)
--------------------------------------------------------------------
Goal: Make the pipeline usable without touching code.

Tasks:
7.1 Build Streamlit app (app.py):
    - File upload widget (CSV)
    - Text box for business problem statement
    - "Run Pipeline" button
    - Progress display (which phase is running)
    - Final report display/download button
7.2 Optionally show intermediate results (EDA summary, model
    comparison table/chart) in the UI

Deliverable: A working Streamlit app wrapping the whole pipeline.

--------------------------------------------------------------------
PHASE 8: TESTING & VALIDATION
--------------------------------------------------------------------
Tasks:
8.1 Test with at least 3 different problem types:
    - A classification dataset (e.g., churn prediction)
    - A regression dataset (e.g., price prediction)
    - A forecasting dataset (e.g., sales forecasting)
8.2 Verify no raw data is ever sent to the LLM (add logging/checks
    on what gets passed to LLM calls)
8.3 Test retry loop triggers correctly when models perform poorly
8.4 Validate report output makes sense and is business-readable

--------------------------------------------------------------------
PHASE 9 (OPTIONAL/ADVANCED): DEPLOYMENT & MONITORING
--------------------------------------------------------------------
Tasks:
9.1 Add model export (pickle/joblib) for the chosen best model
9.2 Add a simple prediction API endpoint (FastAPI) for the deployed
    model
9.3 Add monitoring: track prediction drift or performance decay over
    time
9.4 Add automatic retraining trigger when performance drops below
    threshold

====================================================================
8. KEY SAFETY / DESIGN CHECKLIST (VERIFY THROUGHOUT BUILD)
====================================================================

[ ] LLM prompts only ever include schema, stats, metrics, and text
    context - never raw DataFrame rows
[ ] All data processing happens in local/sandboxed Python code, not
    inside LLM prompts
[ ] Time-series splits are chronological, never randomly shuffled
[ ] Retry loop has a max iteration limit (no infinite loops)
[ ] Sensitive columns (PII) are excluded or anonymized before any
    stats are computed/shared
[ ] Final report avoids exposing individual-level sensitive data,
    only aggregated insights
[ ] API keys (LLM provider) are stored securely (env variables, not
    hardcoded)

====================================================================
9. DECISIONS (RESOLVED OPEN QUESTIONS)
====================================================================

9.1 LLM Provider: Groq-hosted open model (chosen over Claude/GPT for
    lower cost/latency). All planner/evaluator/reporter prompts must
    be built provider-agnostic where reasonable, but implementation
    targets the Groq API first.

9.2 Orchestration Framework: LangGraph (as originally recommended).
    Used for the state graph, retry-loop conditional edges, and node
    definitions described in Phases 4 and 6.

9.3 AutoML Engine: AutoGluon (as originally recommended). Used in
    tools/automl_training.py for training/tuning/comparing candidate
    models across classification, regression, and forecasting.

9.4 PII / Sensitive Column Handling: Manual allowlist/denylist. The
    user specifies which columns are sensitive at ingestion time
    (Phase 1); those columns are excluded from schema stats, EDA
    output, and anything sent to the LLM. No automated PII-detection
    library in v1 - this can be revisited later if needed.

9.5 Planner Output Validation: Pydantic schema with retry-on-failure.
    Define a strict Pydantic model for the Planner Agent's structured
    JSON output (problem type, target column, pipeline steps,
    candidate models). If the LLM output fails validation, re-prompt
    automatically with the validation error included, up to a small
    max-retry count (reuse the same "no infinite loop" principle as
    the evaluator retry logic in Phase 4).

9.6 Deployment Scope (v1): Local single-user use only. Runs via the
    Streamlit app (Phase 7) on the user's own machine. No auth,
    multi-tenancy, or hosted API is required for v1 - Phase 9
    (deployment/monitoring/prediction API) remains optional/deferred
    and should only be revisited if the project moves beyond local
    use.

9.7 Testing Framework: pytest. All Phase 8 tests (tool-level unit
    tests, end-to-end pipeline tests across the 3 problem types, and
    checks that no raw data reaches the LLM) should be written as
    pytest test cases.

9.8 Expected Data Scale: Small/medium datasets that fit comfortably
    in memory (roughly <1-2GB). Plain pandas in-memory processing is
    sufficient for v1; no chunking/streaming ingestion is required.
    Revisit if larger datasets become a requirement later.
